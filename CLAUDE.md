# CLAUDE.md — Sweety (Blood Glucose Tracker)

## What the product is
Sweety is a small web app for a diabetes patient to:
- Record **up to 4 blood glucose readings per day** (a hard limit per user per calendar day).
- View a **daily report** (that day's readings) and a **monthly report** (per-day summaries / stats for a month).

### Frontend rules
- Stack: **Tailwind CSS v4** (no config file; theme in `index.css`), **TanStack Router file-based routing** (not react-router-dom), **react-toastify** for notifications, **lucide-react** icons, font Plus Jakarta Sans.
- New page = new file in `src/routes/` exporting `export const Route = createFileRoute('/path')({ component, beforeLoad? })`. Only route files go in `src/routes/`; components live in `src/components/`.
- Protect pages with `beforeLoad: requireAuth`; guest-only pages with `beforeLoad: requireGuest` (from `lib/guards.js`).
- API calls go through `lib/api.js` `apiRequest()` via a `src/services/<feature>.js` module; pass `{ auth: true }` to send the JWT.
- JWT is stored in localStorage under `sweety_token`.
- Design language: rose brand (`rose-600`), slate neutrals, rounded-xl/2xl, red for errors; status colors emerald = in range, amber = high, sky = low.
- Buttons: `<Button>` or `buttonClasses({ variant, size })` on `<Link>`s. Don't override variant colors via `className` — add a variant.
Feature folder pattern: `src/{routes,controllers,services}/<feature>/<feature>.js` (e.g. `glucose_readings/glucose_readings.js`); middleware is flat (`src/middleware/<name>.js`).
**Architecture (user's rule — MVC-style separation, follow strictly):**
- **routes/** — only map URL + method → (middleware) → controller function.
- **controllers/** — only call the service with request data (`req.body`, `req.query`, `req.params`, `req.user.id`) and **send the response** (status + `{ success, message, data }`); map service errors (`error.status`) to HTTP, else 500. **No validation or business logic here.**
- **services/** — **all business logic**: input validation/normalization, rules (e.g. max 4 readings/day), hashing, tokens, and Supabase queries. Throw an error with a `status` (e.g. `AuthError(message, 400)`) for expected failures.
- **middleware/** — cross-cutting request checks (e.g. `requireAuth`).

`docker compose up -d --build` from the repo root (needs root `.env` from `.env.example`: `POSTGRES_PASSWORD` letters/digits only, `JWT_SECRET`, optional ports). Services:

- `postgrest` (`postgrest/postgrest:v12.2.12`, internal only). It connects as `authenticator` and runs requests as `sweety_api`, with no JWT and `PGRST_DB_MAX_ROWS=1000` like Supabase.
- `redis` (`redis:7-alpine`, cache only, no persistence).
- `backend` (`node:22-alpine`, prod deps, user `node`, host `:3000`).
- `frontend` (built by Node, served by `nginx:alpine` with SPA fallback, host `:8088`; `VITE_API_URL` is a build arg).
- `config/supabase.js`: if `POSTGREST_URL` is set it uses a `PostgrestClient` (`@supabase/postgrest-js`, same `.from()` API); otherwise it uses hosted Supabase. Services must only use `.from()` queries (no `supabase.auth`/`rpc`/`storage`) so both modes keep working.
- Seeding: `seeding-scripts/` (`seed.sql`, `seed.ps1`, `seed.sh`, README) seeds 2 doctors and 6 patients (`*@sweety.test`, password `Password@123`) plus about 90 days of readings, then runs `FLUSHDB` on Redis. It is re-runnable and only replaces `@sweety.test` accounts.

|---|---|---|
| id | BIGINT | PK, auto increment |
| full_name | TEXT | NOT NULL |

## Auth API (`/api/auth`)
- `POST /register` — body `{ role_id (1|2, required), assigned_doctor (doctor's users.id, required when role_id=1, ignored for doctors), full_name, email, password (≥8), phone_number?, date_of_birth?, gender?, blood_group?, height_cm? }` → 201 `{ data: { user, token } }`; 409 duplicate email; 400 validation (incl. "Please choose your doctor", "Please choose a valid doctor").
- Every returned `user` includes `role_id`, `role` ("patient"/"doctor"), `assigned_doctor` and `doctor` (`{ id, full_name, email }` or null).
- `PUT /me` also accepts `assigned_doctor` (patients only; can change, can't clear); `role_id` → 400 "Role can't be changed".
- `POST /login` — `{ email, password }` → 200 `{ data: { user, token } }`; 401 "Invalid email or password" (same message for unknown email / wrong password).
- `GET /me` — header `Authorization: Bearer <token>` → `{ data: { user } }`.
- JWT payload `{ sub: String(users.id), email, role_id }`, HS256 signed with `JWT_SECRET`, expiry `JWT_EXPIRES_IN` (default 7d). Older tokens without `role_id` still work (requireRole looks the role up).
- **Never select/return `password_hash`** except in the login lookup; use the `PUBLIC_COLUMNS` list in the auth service.

## Authorization rule
- Protected routes use `requireAuth`; the owner of all data is **`req.user.id` (= `users.id`)**.
- Every query on user data is scoped by `req.user.id` in code — never trust a user id sent by the client.
- Roles: `requireRole(ROLES.X)` (middleware/requireRole.js, after requireAuth) → 403. `/api/readings` + `/api/reports` = patients only; `/api/doctor/*` (except `/list`) = doctors only.
- A doctor may only read patients where `users.assigned_doctor = req.user.id` (checked by `getAssignedPatient` in services/doctor/doctor.js). Other ids → **404 "Patient not found."** (never 403, so ids don't leak). Doctors have read-only access.

## Doctor API (`/api/doctor`, feature folder `doctor/doctor.js`)
- `GET /list` — **public**: `{ doctors: [{ id, full_name }] }` for the register form / patient settings.
- `GET /patients` — `{ today, from, readings_per_day, totals { patients, logged_today, out_of_range }, patients: [{ ...profile, month_to_date { count, average, highest, lowest, high_count, low_count, today_count, last_reading_at } }] }`.
- `GET /patients/:patientId` — `{ patient }` (profile, no password_hash).
- `GET /patients/:patientId/reports?date=` — same shape as `/api/reports` (reuses reports service, so it shares the patient's cache).
- `POST /patients/:patientId/reports/reset-cache` — hard reset of that patient's cached reports (404 if not assigned).
- `GET /patients/:patientId/readings?…` — same as `/api/readings` list (used by the month chart).

## Gotchas
1. `dotenv` must load in `index.js` *before* requiring `./src/config/supabase` or any route (they read env at require/call time).
2. The backend uses `SUPABASE_SECRET_KEY`, which **bypasses RLS** — scoping every query by `req.user.id` in code is the only ownership protection. (The publishable key fails inserts with `42501` RLS errors.)
3. CORS origins come from backend `FRONTEND_URL` (comma-separated; code default = localhost:5173 + `https://sweety-frontend.vercel.app`). Frontend `lib/api.js` defaults to `https://sweety-sigma.vercel.app` in production builds when `VITE_API_URL` is unset.
4. Express 5 forwards rejected async handlers to error middleware; still return `{ success, message, data }`.
5. Windows dev machine (PowerShell primary; Git Bash available). The project path contains spaces — quote paths. When Docker Desktop is running, Windows reserves some port ranges (e.g. 3999 gives EADDRINUSE with nothing listening) — pick another port. Docker Hub's CDN can fail to download images here; `mirror.gcr.io/library/redis:7-alpine` works.
6. Failed inserts still consume `users.id` sequence values, so ids may have gaps — don't rely on them being contiguous.
7. When deleting test users, delete patients before doctors (`assigned_doctor` is a foreign key to `users.id`).

## Readings (built 2026-11-12)
Table **`glucose_reading`** (singular): `id`, `user_id → users.id on delete cascade`, `reading_date DATE`, `time_slot SMALLINT 0–3`, `glucose_value INTEGER 40–600`, `created_at`, `updated_at`; `UNIQUE(user_id, reading_date, time_slot)`; RLS on (bypassed by the secret key).
- Slots (local-time windows, end exclusive): 0 Before breakfast 6–10 AM (fasting), 1 After breakfast 10 AM–2 PM, 2 After lunch 2–6 PM, 3 After dinner 6–10 PM. Defined in `services/glucose_readings/glucose.js` and `frontend/src/lib/glucose.js` (keep in sync).
- **Slot-window rule (user's rule):** a reading can be added only for *today's* slot whose window is open now (patient tz via `X-Timezone`); past dates, closed slots (= missed) and not-yet-open slots → 400. Edit/delete only while the reading's own slot is still open ("This reading is locked…"). 10 PM–6 AM has no open slot. Frontend: ReadingModal auto-picks today + current slot (value only); `slotState()` / `isReadingEditable()` drive the overview cards (open / Opens at / Missed), locked rows and reminders (missed slots never become "due").
- `GET /api/readings/slots` → `{ today, current_slot, slots: [{ time_slot, label, start, end, window }] }`.
- Reports/charts show the time from **`created_at`** (user's rule). `updated_at` is set manually on update (no trigger).
- Status: low < 70; high > 130 fasting / > 180 after meals; else normal.
- Spec error messages (API and UI must match): "Please enter a glucose value." · "Value must be between 40 and 600 mg/dl." · "You already have an After lunch reading for this date." · "You can add only 4 readings per day." · "Date cannot be in the future."
- "Today" = patient's local day: client sends `X-Timezone` (IANA); fallback `DEFAULT_TIMEZONE` env, then UTC.

**API (all require auth, scoped by `req.user.id`)**
- `/api/readings`: `POST /`, `GET /?page=1&limit=20` (max 200; optional `date` or `from`+`to`; newest first; returns `pagination {page,limit,total,total_pages}`), `GET /slots`, `GET/PUT/DELETE /:id`.
- `/api/reports?date=YYYY-MM-DD` (all three) and `/daily`, `/month-to-date`, `/monthly` — each `{ type, from, to, label, summary {count, highest, lowest, average(1 dp)}, is_empty, empty_message }`; daily also has `readings`. Monthly = whole month *before* the selected date.
- Report caching (Redis): every report response also has `cache` = `hit | partial | miss | off`. Keys `sweety:reports:<userId>:v<ver>:<type>:<date>` (TTL `REPORTS_CACHE_TTL_SECONDS`, default 3600) + `sweety:reports:<userId>:ver`. Reading create/update/delete → `reportsCache.invalidate(userId)` bumps the version (old keys ignored, then expire). Invalidations that fail while Redis is down are queued in-process and applied before the next cache use. Redis down/unset → reports read from Supabase, requests never fail because of the cache.
- `POST /api/reports/reset-cache` — hard reset: bump version + delete the patient's report keys → `{ cache: enabled|unavailable|disabled, cleared, deleted_keys }`. Frontend: **Hard reset** button (`components/reports/HardResetButton`) on /dashboard/reports and the doctor's patient page.
- `/api/auth`: `PUT /me` (partial profile update → `{ user, token }`), `PUT /password` (`{ current_password, new_password }`; wrong current → 400, not 401).

**Frontend dashboard**: overview (today's 4 slot cards, stats, month chart, reminders, monthly summary), readings (paginated table + date filter), reports (date picker, 3 report cards, daily list, month line chart with table view), reminders (per-slot times, browser notifications; stored in localStorage, fire only while a tab is open), settings (profile + password).

**Frontend doctor area** (built 2026-11-13): `routes/doctor.jsx` (layout, `requireDoctor`, `components/doctor/DoctorShell`), `routes/doctor/index.jsx` (/doctor: patient list + month-to-date stats + search), `routes/doctor/patients/$patientId.jsx` (read-only reports, daily readings, month chart), `routes/doctor/settings.jsx` (name/email/phone + password).
- Guards (`lib/guards.js`): `requirePatient` on /dashboard, `requireDoctor` on /doctor, `requireGuest` → role home. The role for guards comes from decoding the JWT (`lib/roles.js` `tokenRole()`, routing only — not security); `homeFor(role)` = `/doctor` or `/dashboard`.
- Register: role cards (required) → patients must pick a doctor (dropdown from `/api/doctor/list`); health details only for patients.
- Patients without a doctor (pre-role accounts) see a banner in AppShell → `/dashboard/settings#doctor` (`components/settings/DoctorPicker`).
- Shared: `components/settings/{ProfileForm (fields prop), PasswordForm, DoctorPicker}`, `components/dashboard/UserMenu` (settingsTo prop), `MonthChart` (`fetchReadings`, `emptyText` props), `ReportCard` (`emptyText`), `lib/people.js` (initials, ageFrom, genderLabel).
